Key takeaways

Background

An asset-backed securitization pools thousands of loans or leases and issues notes against them. Every month a servicer collects the cash and a trustee distributes it through the waterfall: the priority of payments in the deal's legal agreements. Fees come first, then each class's interest, then principal by the deal's own rules, then reserve top-ups, and whatever is left goes to the residual holder.

Getting it wrong means mispaying investors. The rules sit in hundreds of pages of prospectus and closing agreements: day-count conventions, overcollateralization targets, step-downs, prorations. One wrong definition carries through every line below it.

WaterfallBench asks a model to do the trustee's job for a deal's first distribution date. It gets the deal documents and that month's servicer report with every waterfall result removed, and nothing else: no prior report to copy from and no worked example. It must return the servicing fee, each note class's interest, principal and ending balance, the reserve balance and the residual release, all in exact cents.

Results

The frontier models solve nearly every deal end to end; Claude Haiku 5.5 gets most lines right but rarely all of them. GPT-6 Luna matches the leaders' field accuracy at about one hundredth of GPT-6 Astra's cost.

The audit found three eval errors

Before trusting the scores, every run was audited: logs, documents sent, parsing, and a local re-grade of each saved reply. Fields where two models from different labs gave the same wrong value pointed to the eval, not the models. Three findings came out of that:

Methodology

Harness

Every model gets the same single API call: a fixed system prompt, then the documents and the task. There are no tools, no code execution and no second turn, so the comparison is the model alone. The harness converts the EDGAR HTML to text (table rows kept as cell | cell lines) and packs the servicer report, the prospectus and then the closing agreements under a 1M-token input cap. No task needed truncation. Reasoning effort is high for every model, and the raw reply is saved to disk before it is parsed.

One fixed answer schema

Every task uses the same answer_schema.json, byte for byte. The model lists the deal's note classes itself; the grader matches them by name, so A-2A, Class A-2a Notes and a2a are the same class.

{
  "servicing_fee_paid": 0,          // integer US cents
  "reserve_ending_balance": 0,
  "released_to_residual": 0,
  "classes": [
    {"class": "A-1", "interest_paid": 0, "principal_paid": 0, "ending_balance": 0}
  ]
}

Grading

  • Fully resolved (primary): 100% when every graded field is exact to the cent, 0% otherwise.
  • Non-trivial field accuracy: share of fields right among those that are non-zero and not just an untouched opening balance.
  • Field accuracy and within $1: all graded fields, exact and within one dollar (rounding slips vs logic errors).

Grading is deterministic: no LLM judge. Cost uses each provider's list price for the tokens it reported, including OpenAI's long-context rate for prompts over 272K tokens.

Dataset

Each task is a deal's first distribution date, taken from the first Form 10-D the trust filed on SEC EDGAR. The packet holds the final prospectus, the closing-date agreements and that month's servicer report as filed, with every waterfall output removed. Collections, pool data, rates and dates stay. Documents were retrieved with Firecrawl; nothing was generated or imputed.

How every task was checked

  • The classes in the report match the classes in the prospectus cover table.
  • For every class, opening balance minus principal paid equals the ending balance, to the cent.
  • Class interest and principal add up to the report's own totals, and every report passes its own cash reconciliation.
  • A value scan finds no graded answer left in the redacted report or the instructions.
  • The true answer, submitted in the fixed schema, grades 100%; an all-zeros answer fully resolves nothing.

Access

All 20 task packets are public in the repository. The answer keys are not: they live only with the grading service, which runs as a Valkyrie benchmark service. Navient was part of the pilot but has no first distribution in range: its only public trusts closed in 2014–15, and its later deals are private placements that file no 10-D.

Run it

valkyrie run start --benchmark waterfallbench --dataset full-html \
  --agent waterfallbench-direct --model anthropic/claude-haiku-5-5 \
  -k effort high -s ANTHROPIC_API_KEY anthropic-api-key --concurrency 5
