Can a model execute an ABS waterfall to the cent?

WaterfallBench tests whether a model can read a securitization's legal documents and compute its monthly payments to investors exactly as the trustee did, to the cent. The answer key is what the trustee actually paid, as filed with the SEC.

The task

What a waterfall is

An asset-backed security turns thousands of car loans or leases into bonds, sold in classes from senior (A) to junior (B, C). Every month the borrowers' payments are collected and paid out in a fixed order of priority, the waterfall:

Collections this monthloan payments, payoffs and recoveries
  • 1Servicing feeto the servicer that collects the loans
  • 2Interestsenior classes first
    • Class A notesA-1, A-2, A-3, A-4 share pro rata
    • Class B
    • Class C
  • 3Principalone class at a time, until each is paid off
    • A-1→A-2→A-3→A-4→B→C
  • 4Reserve accounttopped up to its required level
  • 5Residualwhatever is left, to the equity holder

Each step is paid only from the cash left after the steps above it. Simplified: each deal's agreements set the exact order, amounts and targets.

Why it matters

Securitization funds a large share of US car loans and leases: the 20 deals in this benchmark alone issued $23.5 billion of notes. The waterfall decides who gets paid and in what order, so an error moves cash between senior and junior investors, and because each month starts from the last month's balances, it carries forward. Today this is done with deal-specific cash-flow models built by hand from the documents. WaterfallBench asks whether a model can read the documents and get it right on its own.

What the model gets

A deal's first distribution date. Opening balances come from the prospectus, so there is no prior report to copy from. All documents are EDGAR HTML as filed:

InputFiled asWhat the waterfall needs from it
Final prospectus424(b)(5)Note classes, coupons, day counts, the priority of payments
Closing agreements8-K exhibitsIndenture and servicing agreements: the fee, reserve and overcollateralization definitions
Servicer report10-D Ex. 99.1That month's collections, pool balances, rates and dates, with every waterfall result removed

It must return the servicing fee, each class's interest, principal and ending balance, the reserve balance and the residual, in integer cents. Here is the report from a real task as the model sees it:

Dataset

Tokens: mean prompt per task, Claude tokenizer, as sent by the harness. No task needed truncation.

Release checks

Every task passed these checks: the report's classes match the prospectus; each class's opening balance minus principal paid equals its ending balance, to the cent; class payments add up to the report's totals; no graded value is left in the packet; and the true answer grades 100% while an all-zeros answer resolves nothing.

Methodology

Harness

One API call per task: a fixed system prompt, the documents and the task. No tools, no code execution, no second turn, so the comparison is the model alone. EDGAR HTML is converted to text with table rows kept as cell | cell, then packed (report, prospectus, agreements) under a 1M-token cap; no task needed truncation. Reasoning effort is high for every model.

Evaluation metrics

Every task uses the same answer schema, given in the prompt. The model's reply is parsed, its classes are matched to the deal's by name, and every field is compared with the filed value, exactly.
